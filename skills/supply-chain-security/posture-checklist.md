# Supply-chain posture checklist

Reference checklist, modelled on the OpenSSF Scorecard checks (risk level
in brackets) and SLSA Build track. Record the date, result and owner of
each open item in the project's docs.

## Repository

- [ ] Branch protection on the default branch and release tags: required review, required checks, no force-push (High)
- [ ] Changes are reviewed before merge (High)
- [ ] No compiled binaries committed that cannot be rebuilt from source (High)
- [ ] License declared at the root (Low) and per file (see `license-compliance`)
- [ ] Security policy present: how to report a vulnerability, response time (Medium)
- [ ] Project actively maintained; issues answered (High)

## Pipeline

- [ ] No dangerous trigger patterns: untrusted PR code never runs with secrets or write tokens; untrusted text never interpolated into shell (Critical)
- [ ] Workflow tokens read-only by default, write scopes per job (High)
- [ ] Third-party steps, images and tools pinned by hash/digest (Medium)
- [ ] Downloads verified by checksum or signature
- [ ] Tests run in CI on every PR (Low)
- [ ] Static analysis runs in CI (Medium)
- [ ] Fuzzing where inputs are untrusted (Medium)
- [ ] Webhooks authenticated (Critical)

## Dependencies

- [ ] Dependency update tool configured (High)
- [ ] No unfixed known vulnerabilities in shipped dependencies (High)
- [ ] Lockfiles committed with hashes

## Releases

- [ ] Packages built and published from CI, not by hand (Medium)
- [ ] Releases signed; signatures and checksums published (High)
- [ ] SBOM attached to each release (SPDX or CycloneDX, CISA minimum elements)
- [ ] Provenance generated by the build platform (SLSA Build L1), signed (L2), from isolated builders with unreachable signing keys (L3)
- [ ] Publish step verifies provenance before upload
